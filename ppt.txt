1. 목적

자기 부상 제어 기술의 중요성
●최근 도심형 자기부상열차나 전기차의 정밀 자기 베어링, 초정밀 반도체 공정 장비 등에서 마찰과 소음을 최소화하는 자기 부상
(Magnetic Suspension) 제어 기술의 중요성이 커지고 있다. 이러한 시스템은 본질적으로 매우 불안정한 비선형 특성을 가지므로, 정밀하고 신뢰성 있는 제어 알고리즘 설계가 필수적이다.

●따라서 본 과제는 자기력으로 금속 구(Magnetic ball)를 공중에 띄워 목표 위치에 안정적으로 유지하는 시스템 을 바탕으로, 비선형 시스템의 선형화, 상태 공간 모델링, 그리고 연속 시간(CT) 및 이산 시간(DT) 영역에서의 상태 피드백 제어기 및 관측기 설계를 수행하여 실무적인 제어 공학 역량을 기르는 것을 목적으로 한다.

# r을 바꿀 때마다 
	->
	1. 선형화의 치명적 한계: "직선은 곡선을 오직 한 점에서만 대변한다"자기부상 시스템(MBS)의 자력은 거리의 제곱에 반비례($1/x^2$)하는 극악의 곡선(비선형)입니다. 우리가 $y_0 = 0.01$ (1cm)에서 선형화했다는 것은, 그 곡선 위의 1cm 지점에 접선(직선)을 그은 것과 같습니다.1.1cm로 갈 때 ($r = 0.011$): 1cm와 1.1cm는 매우 가깝기 때문에, 실제 곡선과 우리가 그은 접선(A, B 행렬)의 오차가 거의 없습니다. 제어기가 아주 잘 작동합니다.2.0cm로 갈 때 ($r = 0.020$): 1cm와 2cm는 물리적으로 엄청난 차이입니다(자력이 1/4로 떨어짐). 우리가 그어놓은 1cm 기준 접선과 2cm 지점의 실제 물리 법칙(곡선)은 완전히 어긋나 있습니다.
	2. 매트랩 선형 시뮬레이션의 달콤한 거짓말여기가 가장 중요한 포인트입니다!만약 지금 질문자님의 매트랩 코드(선형 모델 sys_acker)에 목표 편차를 크게 줘서 $\Delta r = 0.05$ (5cm 이동)를 넣고 돌리면 어떻게 될까요?매트랩의 대답: "정착 시간 0.5초 만에 완벽하게 6cm(1cm+5cm)에 도달했습니다!" 라고 예쁜 그래프를 그려줍니다.왜 그럴까요? 매트랩의 lsim 함수는 실제 비선형 물리 법칙($1/x^2$)을 시뮬레이션하는 것이 아니라, 질문자님이 넣어준 A, B 행렬(무한히 뻗어나가는 끝없는 직선)을 시뮬레이션하기 때문입니다. 선형 모델 안에서는 100km를 이동하라고 해도 완벽하게 이동하는 것처럼 거짓말을 합니다.하드웨어의 현실: 똑같은 제어기(1cm 기준 K 매트릭스)를 라즈베리파이에 넣고 가변저항을 6cm로 돌리면? 모터 전압이 미쳐 날뛰다가 긴급 차단(E-Stop)이 걸리거나 구슬이 추락합니다.
	3. 현업에서는 목표치($r$)가 바뀔 때 어떻게 대처하는가?자율주행차나 로봇 팔처럼 목표 위치가 수시로 크게 변하는 시스템을 위해, 현업 엔지니어들은 다음 3가지 중 하나의 전략을 택합니다.① 강인 제어 (Robust Control) - "그냥 버틴다"목표치가 0.8cm ~ 1.2cm 정도로 조금만 변한다면? 1cm 기준으로 만든 행렬 하나만 씁니다. 제어기(LQR 등) 자체에 오차를 극복하는 힘(안정성 여유)이 있기 때문에 약간의 오차는 씹어먹고 제어해 냅니다.② 게인 스케줄링 (Gain Scheduling) - "구간별로 바꿔치기"목표치가 1cm ~ 4cm로 크게 변한다면? 질문자님의 생각대로 "매번 평형점을 다시 계산"하는 것이 맞습니다.현업에서는 1cm용 K행렬, 2cm용 K행렬, 3cm용 K행렬을 미리 다 매트랩으로 계산해서 C 코드 배열에 저장해 둡니다. 그리고 구슬이 2cm를 지나갈 때는 2cm용 행렬로 실시간 스위칭(Interpolation)을 해버립니다. (비행기 오토파일럿이 고도/속도에 따라 제어 행렬을 바꾸는 방식입니다.)③ 피드백 선형화 (Feedback Linearization) - "비선형 제어"아예 A, B 행렬을 구하는 선형화(Taylor 전개)를 포기합니다. C 코드 자체에 비선형 수식($1/x^2$)의 역함수를 넣어서 수학적으로 비선형성을 통째로 지워버리는 고급 제어 기법을 사용합니다.
	💡 결론 및 현재 코드 적용 가이드질문자님께서 "r을 바꿀 때마다 행렬을 다시 계산해야 하나?"라고 물으신다면, "하드웨어(C 코드)에서 넓은 범위를 움직이고 싶다면 당연히 그렇게 해야 한다"가 정답입니다.현재 매트랩 시뮬레이션에서 할 일:1cm 근처의 미세한 스텝 이동(예: 1cm -> 1.1cm)을 보고 싶다면, 현재의 y0 = 0.01 행렬을 그대로 두고 $\Delta r = 0.001$ 편차만 주면 됩니다.만약 2cm에서의 거동을 정확히 설계하고 싶다면, y0 = 0.02로 코드를 수정해서 스크립트를 새로 한 번 싹 돌리고, 그때 나온 완전히 새로운 K, L, Nbar 값들을 C 코드에 넣으셔야 실제 하드웨어가 2cm에서 안정적으로 버틸 수 있습니다!

# 실시간 제어에서 CSV 저장을 해도 되는가? (현업의 방식)
	-> "이런 I/O 코드를 넣어도 되나? 타격 없나?" 타격이 엄청납니다! 매우 위험한 동작입니다.SD 카드나 저장장치에 파일(.csv)을 쓰는 동작은 CPU가 엄청나게 오랜 시간(수 밀리초 이상) 대기해야 하는 블로킹(Blocking) 작업입니다. 1ms 주기를 칼같이 지켜야 하는 제어 루프에서 파일 저장을 남발하면, 제어 주기가 밀려버리는 지터(Jitter) 현상이 발생하여 시스템이 발산할 수 있습니다.
	-> [현업에서는 어떻게 하는가?]현업(자동차 ECU, 로봇 제어기)에서는 실시간 제어 루프를 방해하지 않기 위해 철저한 메모리 분리를 사용합니다.
ISR (제어 루프): 파일 저장은 절대 하지 않고, 처리 속도가 가장 빠른 RAM 메모리의 큰 배열(Ring Buffer)에 데이터만 차곡차곡 쌓아둡니다. (시간 소모 거의 0)
Background Task (하위 우선순위): 제어 연산이 끝나고 남는 자투리 시간에, 램에 쌓인 데이터를 모아서 한 번에 SD 카드에 쓰거나 고속 통신(CAN, Ethernet)으로 외부 PC에 쏴줍니다.
현업의 적용 방법 (멀티스레딩):
C언어에서 pthread 라이브러리를 사용해 두 개의 일꾼(Thread)을 만듭니다.
고순위 스레드 (제어 루프): 1ms마다 연산을 끝내고, RAM에 만들어둔 배열(링 버퍼)에 변수값 5개를 0.0001ms 만에 휙 던져놓고 곧바로 다음 제어를 준비합니다.
저순위 스레드 (로깅 데몬): CPU가 남는 시간에 링 버퍼를 슬쩍 쳐다보다가, 데이터가 어느 정도 쌓여있으면 그것들을 한 번에 묶어서 SD 카드(csv)로 천천히 씁니다.
이렇게 코드를 짜면 실시간 제어를 전혀 방해하지 않고도 완벽한 로깅이 가능합니다.
	-> 우리가 사용하는 리눅스 유저 모드(User-space)에서는 하드웨어 타이머를 직접 건드리는 '진짜 ISR(Interrupt Service Routine)'을 애초에 만들 수가 없습니다. 운영체제가 막아두었기 때문입니다.
현재 코드의 정체: 현재 사용 중인 gpioTick()으로 시간을 재고 gpioDelay()로 남은 시간만큼 쉬는 방식은 ISR이 아니라 '정밀 타이머 폴링(Soft Real-Time Polling)'입니다. 그리고 리눅스 유저 모드 환경에서는 이 방식이 우리가 할 수 있는 최선이자 가장 정석적인 방법이 맞습니다. (아두이노 같은 OS 없는 보드에서만 진짜 ISR을 씁니다.)
CSV 주석 처리: 아주 탁월한 선택입니다! 실시간 제어에서 파일 입출력을 막은 것은 시스템의 안정성을 극대화하는 최고의 조치입니다. 나중에 멀티스레딩(스레드 1: 제어, 스레드 2: 링버퍼 읽어서 CSV 저장)을 공부해서 적용하시기 전까지는 끄고 진행하시는 것이 맞습니다. <pthread.h>를 이용해 '제어 스레드(우선순위 높음)'와 '로깅 스레드(우선순위 낮음)'를 나누고, 그 사이를 '링 버퍼(Ring Buffer)'로 연결하는 코드를 구현

# 커널 모드에서는 데이터 저장이 힘드니 폐기하는 게 맞나?
	-> 커널의 엄격함: 커널 모드 ISR(하드웨어 인터럽트) 안에서는 fopen, fprintf 같은 파일 입출력 함수를 단 하나라도 쓰는 순간 리눅스 전체가 뻗어버립니다(Kernel Panic). 커널은 하드웨어를 직접 다루는 신성한 구역이라 느린 파일 저장을 용납하지 않습니다.
	-> 현업의 해결책 (Kernel to User 통신):
현업에서는 ISR 안에서 데이터를 제어한 뒤, 리눅스 커널에서 제공하는 커널 전용 링 버퍼(kfifo)나 통신 소켓(Netlink)을 통해 데이터를 '유저 모드(우리가 평소 쓰는 리눅스 환경)'로 쏘아 올립니다. 그러면 유저 모드에서 백그라운드로 돌고 있는 다른 C 프로그램이 그 데이터를 넙죽 받아서 CSV 파일로 예쁘게 저장합니다. 즉, 제어(커널)와 저장(유저)을 두 개의 프로그램으로 완전히 분리하는 것이 정석입니다.

10. 결론

정밀 제어 공학의 실무적 통찰 획득
본 과제를 통해 본질적으로 매우 불안정한 자기 부상 시스템을 수학적으로
정밀하게 선형화하고, 상태 피드백 제어기와 관측기를 결합하여 안정화하는
제어 공학의 핵심 실무를 직접 경험한다.
이론적으로 구축된 연속 시간(CT) 제어 모델을 실제 디지털 환경으로
이식하기 위한 이산 시간(DT) 변환 메커니즘을 심층 분석함으로써,
향후 고도화된 실무 임베디드 제어 시스템 설계에 필수적인 유의미한
엔지니어링 역량을 확보할 것으로 기대한다.
